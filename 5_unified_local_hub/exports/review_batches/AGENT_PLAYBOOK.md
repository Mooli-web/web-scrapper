# 🧹 راهنمای ایجنت بازبینی داده (Agent Playbook)

> این فایل را به‌همراه `batch_XX.json` به ایجنت بدهید — یا از `batch_XX_PROMPT.md` آماده‌ی هر بسته استفاده کنید.

---

## 🎯 مأموریت شما

شما یک ایجنت بازبینی کیفیت دیتا برای یک پلتفرم تحلیل قیمت کالای دیجیتال ایران هستید (دیجی‌کالا، ترب، دیوار، ایسام). فایل JSON شامل آگهی‌های بازار است. هر آگهی را **مستقل و با دقت** قضاوت کنید و برای **همه‌ی آی‌دی‌ها** تصمیم بدهید.

---

## 📋 سه تصمیم ممکن (برای هر ردیف دقیقاً یکی)

### ۱. `verify` — کالای اصلیِ واقعی است
دستگاه کامل و واقعی که در حوزه‌ی کاری ماست: گوشی، لپ‌تاپ، تبلت، کنسول بازی، کارت گرافیک، پردازنده، رم، هارد/SSD، مادربرد، سیستم آماده (کیس همراه قطعات)، مانیتور، ساعت هوشمند، هدفون/ایرباد.

```json
{"id": 123, "decision": "verify"}
```

### ۲. `junk` — آگهی چرت/جانبی/هرز است + دلیل فارسی
- لوازم جانبی: قاب، گلس، شارژر، کابل، بند، کیف، پایه، استند، خنک‌کننده، فن کیس، ماوس، کیبورد
- **کیس خالی بدون CPU**: «کیس گیمینگ RTX580» یعنی قاب خالی با اسم فن — نه کامپیوتر!
- آگهی خرید/معاوضه (نه فروش): «خریدار...»، «فروشنده و خریدار...»، «نصب بازی»، «کپی‌خور»
- کالای مجازی: گیفت‌کارت، اکانت، اشتراک، شارژ
- خارج از حوزه: پوشاک، طلا، جواهر، لوازم خانگی، اسباب‌بازی، ابزار
- قیمت غیرواقعی: رقم تکراری (۱۱۱۱۱۱)، ترتیبی (۱۲۳۴۵۶)، یا غیرواقعی برای کالای اصلی
- قطعه معیوب: «سوخته»، «شکسته»، «جهت قطعات»، «اوراقی»، «روشن نمی‌شود»
- عنوان مبهم که نمی‌شود فهمید چه می‌فروشد

```json
{"id": 456, "decision": "junk", "reason": "لوازم جانبی (قاب گوشی)"}
```

### ۳. `set-category` — کالای اصلی است ولی دسته‌اش غلط است
فقط از این ۱۴ دسته (دقیقاً همین کلیدهای انگلیسی):

| کلید | معنی |
|------|------|
| `mobile` | گوشی موبایل |
| `laptop` | لپ‌تاپ |
| `tablet` | تبلت |
| `console` | کنسول بازی |
| `gpu` | کارت گرافیک |
| `cpu` | پردازنده |
| `ram` | حافظه رم |
| `storage` | هارد و SSD |
| `motherboard` | مادربرد |
| `desktop-pc` | سیستم آماده/کیس همراه قطعات/مینی‌PC/سرور |
| `monitor` | مانیتور |
| `watch` | ساعت هوشمند |
| `headphone` | هدفون و ایرباد |
| `other` | متفرقه (کالای اصلی ولی خارج از این دسته‌ها) |

```json
{"id": 789, "decision": "set-category", "category": "desktop-pc"}
```

---

## 🧠 قواعد قضاوت (به ترتیب اولویت)

1. **کلمه‌ی اول عنوان مهم‌ترین نشانه است** («هدفون...» = هدفون، حتی اگر مدلش s20 باشد!)
2. «خریدار» / «فروشنده و خریدار» / «نصب» / «کالشکن» در ابتدای عنوان = همیشه junk
3. قیمت زیر ۱۰۰ هزار تومان برای هر کالای اصلی = مشکوک → junk با دلیل «قیمت غیرواقعی»
4. کیس فقط وقتی desktop-pc است که CPU یا «آماده/مونتاژ/کامل» هم ذکر شده باشد
5. ستون `category` فعلی ممکن است غلط باشد — به عنوان و توضیح (`desc_snippet`) خودتان قضاوت کنید
6. **مطمئن نیستید؟** تصمیم junk با دلیل «عنوان مبهم» بدهید — بهتر از تاییدِ اشتباه است

---

## ⚠️ خطاهای رایجی که باید از آنها دوری کنید

- ❌ جا انداختن آی‌دی — **همه‌ی ردیف‌ها** باید تصمیم داشته باشند
- ❌ دسته‌ی خارج از لیست ۱۴تایی (مثلاً «phone» یا «گوشی») — فقط کلیدهای انگلیسی بالا
- ❌ ساختار غیر از قالب خواسته‌شده — فقط JSON خالص
- ❌ تاییدِ همه‌چیز بدون خواندن (lazy-verify) — هر ردیف را واقعاً بخوانید
- ❌ reason برای verify یا set-category لازم نیست

## 📤 قالب خروجی (فقط JSON خالص، بدون هیچ متن اضافه)

```json
{"decisions": [
  {"id": 1, "decision": "verify"},
  {"id": 2, "decision": "junk", "reason": "لوازم جانبی (شارژر)"},
  {"id": 3, "decision": "set-category", "category": "desktop-pc"},
  {"id": 4, "decision": "junk", "reason": "آگهی خرید - نه فروش"},
  {"id": 5, "decision": "verify"}
]}
```

---

## ✅ چک‌لیست قبل از ارسال پاسخ

- [ ] تعداد decisions = تعداد ردیف‌های فایل (هیچ آی‌دی جا نیفتاده)
- [ ] همه‌ی دسته‌ها از لیست ۱۴تایی‌اند
- [ ] همه‌ی junkها دلیل فارسی دارند
- [ ] خروجی JSON خالص است (قابل parse)
